# 讲座/录屏切片方法论（五步工作流）与坑清单

## 五步工作流

### 第 1 步：素材体检与内容规划
1. `analyze_source.py --src <素材>` 拿到时长/分辨率/帧率/流结构。
2. ASR 转写全片（whisper / 讯飞），拿到带时间戳的字幕稿；若 probe.wav 是从源片某偏移截取的，
   ASR 返回的是**相对秒数**，必须先校正 offset（见坑 1）。
3. 根据转写稿挑选重点，规划成片叙事结构：
   - 片头钩子（Hook）：一句话戳痛点 + 红色副题，占 2–3 秒
   - 主体：按"问题 → 是什么 → 为什么 → 怎么做"或原片逻辑顺序选段
   - 片尾卡（EndCard）：关注引导，占 2–3 秒
4. 每个选段的入出点先用秒级草稿，再落到帧级确认（第 2 步）。

### 第 2 步：切点帧级确认 + 素材预处理
1. **切点必须帧级确认，不许凭秒级估算**：
   - `analyze_source.py --jumps FROM TO` 帧差扫描定位镜头跳变/分屏切换（精度 1 帧）。
   - `analyze_source.py --silence` 找说话停顿，剪辑点对齐停顿处。
   - 人像/画面要素在位的精确边界：`portrait_scan.py --from X --to Y --step 0.25`，
     再对边界 ±2 秒逐帧（step≈1/30）扫描，找到第一个消失/出现的帧号。
2. **素材预处理**（源画质差时）：
   - 有更高清的原始源时，用高清源重处理替代低清放大：裁切有效区域 →
     `lanczos` 下采样到目标分辨率 → `unsharp` 锐化（0.3 左右）→ `crf 10–12` 中间素材。
   - 裁切/缩放后宽高必须为**偶数**（h264 要求），奇数会报错（见坑 2）。
   - 中间素材不要过度编码（crf≤12），成片再压一次会叠加损失。
3. 音轨从源片截取或重录；停顿过多时可按 silencedetect 结果剪掉长停顿再拼回，
   拼完 `loudnorm=I=-16:TP=-1.5:LRA=11` 归一化。

### 第 3 步：Remotion 精剪工程
1. 复制 `assets/remotion-template/`，`npm i`；素材放 `public/`。
2. `core.ts` 里填 SEGMENTS：每段 {file, from, dur, startFrom, fadeIn}。
   - 相邻段**硬切对齐**（前段 from+dur == 后段 from），Sequence 不允许重叠（见坑 4）。
   - 接缝用 fadeIn 3 帧软化，但只淡入新段，不要两头都淡（会闪黑）。
3. 缺口/瑕疵段修复策略（按优先级）：
   1. **整段借入连续真实画面**（首选）：从同素材其他位置借一段帧数相同的连续画面顶上，
      观感是连续真人画面，无静帧无贴片违和感。
   2. 画中画补丁：小窗贴别处人像（次选，容易违和；边界要外扩 2–3 帧防漏）。
   3. 静帧定格（保声音换画面）：仅 1–1.5 秒内可用，再长就假。
4. 视觉设计规范：
   - 字体：Noto Sans SC 700/800/900（黑体），**禁用宋体**（用户反馈"没力气"）。
   - 字幕：720p 下 30px 白字、深色半透明底、关键词红色（#ff5a52）；每条 ≤ 22 字。
   - 页边注释（录屏课）：只放左右空白区，纸色 `rgba(251,248,243,0.93)` + 砖红左边线，
     **绝不遮挡讲解区/代码区**。
   - 底部进度条 6px 主题色；人像小窗放右下角。

### 第 4 步：渲染与混音
1. 渲染命令（Windows，无 Chrome 时用 Edge）：
   ```
   npx remotion render Clip out/clip_vX.mp4 --browser-executable="C:/Program Files (x86)/Microsoft/Edge/Application/msedge.exe" --gl=angle --concurrency=6 --crf=12 --codec=h264
   ```
   渲染可后台跑；完成后先做解码校验再交付：
   `ffmpeg -v error -i out/clip_vX.mp4 -f null -`（输出为空即无损）。
2. 音轨垫片对齐：成片含片头钩子时，音轨前垫 2.5–3 秒静音；片尾垫 2 秒左右。
   `mix_audio.py --video out/clip_vX.mp4 --audio vo.wav --out final.mp4 --pad-before 3.0 --pad-after 2.4`
   （内部执行：视频 copy、音频 aac 192k、-shortest、+faststart。）

### 第 5 步：验证与交付
1. **交付前必须机器验证，用户说"确认没问题"才算完**：
   - 全片解码零错误；
   - 关键修复段（借入/补丁/定格）用 `portrait_scan.py` 每 0.5 秒抽帧确认人像/画面全程在位；
   - 音画对齐：抽查片头、接缝、片尾三处声音与画面节奏一致；
   - 时长 = 钩子 + 主体 + 片尾（±0.2s）。
2. 覆盖桌面同名成片交付；文件名带上主题（如 `主题-90秒.mp4`）。

## 坑清单（每条都真实踩过）

1. **ASR 相对秒数坑**：probe.wav 从源第 560 秒截取转写，返回秒数是相对截取点的；
   直接当绝对秒用 → 切片前 17 秒全是静音。修复：取 ASR 假设位置与实际位置的音频做
   能量包络匹配（互相关），求出 offset 修正全部时间戳。
2. **ffmpeg 偶数宽高**：rawvideo / 裁切 / scale 输出宽高必须偶数，1147×620 直接报错；
   一律取整到偶数（1148×620）。
3. **多源时间轴偏移**：同一讲座的低清源与高清源切点差 0.1 秒（编码起点不同）。
   跨源对齐时把定格/切换区间放宽 ±0.1–0.15 秒。
4. **Remotion Sequence 重叠边界 bug**：借入段与后段交接时若 Sequence 有重叠，
   前段会在交接帧提前 4 帧截断，导致接缝处要素（人像）闪断。修复：非重叠硬切 +
   每段自己 fadeIn；切点用帧级扫描精确到"要素在帧 N 消失"那帧。
5. **静帧/贴片违和**：用户对假画面的违和感极敏感（"突然闭眼睛""很违和"）。
   缺口修复首选整段借入连续真实画面；补丁窗口的起点要选低头的自然衔接帧。
6. **音画分离架构**：画面用 Remotion 排（帧号驱动），声音用独立音轨（秒对齐）。
   剪辑画面不会产生声音停顿，因为声音是一条连续整轨；停顿靠第 2 步剪停顿解决。
7. **yuvj420p 全量程**：源是 yuvj420p 时直接重编码亮度会变化，比对截图时注意；
   中间素材保持一致的 pix_fmt。
8. **水印/遮盖**：先确认源素材本身有无水印，再决定要不要遮盖块；高清源可能无
   低清源的水印，多余的灰色遮盖块要删掉。
9. **交付覆盖**：桌面上保留固定文件名，新版本直接覆盖同名文件（用户不要备份副本）。
10. **渲染中断**：长渲染放后台跑（run_in_background），502 等网络错误中断后先查
    out/ 文件时间戳和解码校验，不完整才重渲。
